### 3. WebSocket 实时推送

#### 连接

```javascript
const ws = new WebSocket('ws://localhost:8000/ws/diagnosis/diag-20250110120000-user-service');

ws.onopen = () => {
  console.log('WebSocket connected');
};

ws.onmessage = (event) => {
  const data = JSON.parse(event.data);
  console.log('Message:', data);
  
  // 处理不同类型的消息
  switch (data.type) {
    case 'connected':
      console.log('Connection established');
      break;
    case 'progress':
      console.log(`Progress: ${data.progress}%`);
      break;
    case 'completed':
      console.log('Diagnosis completed');
      break;
    case 'error':
      console.error('Error:', data.message);
      break;
  }
};

// 发送 ping 保持连接
setInterval(() => {
  ws.send(JSON.stringify({ type: 'ping' }));
}, 30000);
```

#### 消息格式

**服务端 → 客户端**：

```json
// 连接成功
{
  "type": "connected",
  "session_id": "diag-20250110120000-user-service",
  "message": "WebSocket connection established"

// 进度更新
{
```

## 🔧 技术决策

### 1. 异步框架选择：FastAPI

**理由**：
- 原生支持 async/await
- 自动生成 API 文档
- 类型注解与 Pydantic 集成
- 性能优异（基于 Starlette）
- 社区活跃

**替代方案**：
- Flask：同步框架，需要 Gunicorn + gevent
- Sanic：异步框架，但文档和生态不如 FastAPI

### 2. WebSocket 管理

**连接管理器设计**：
- 单例模式（全局 manager 实例）
- 字典存储活跃连接（`session_id` -> `WebSocket`）
- 自动断开失败连接

**消息格式**：
- JSON 格式
- 包含 `type` 字段区分消息类型
- 包含 `session_id` 字段标识会话

### 3. 错误处理策略

**分层错误处理**：
1. **用例层**：抛出领域异常（如 `DiagnosisAlreadyInProgressError`）
2. **路由层**：捕获异常并转换为 HTTP 异常
3. **中间件层**：统一处理未捕获异常

**优点**：
- 领域层保持纯粹
- 路由层处理业务异常
- 中间件兜底处理意外异常

### 4. CORS 配置

**当前配置**：
- 仅允许本地开发地址
- 允许所有方法和头

**生产环境建议**：
- 配置具体的生产域名
- 限制允许的方法
- 限制允许的头

### 5. API 版本管理

**路径前缀**：`/api/v1/...`

**优点**：
- 便于未来版本迭代
- 不破坏现有客户端

**未来**：
- `/api/v2/...` 引入新功能
- 保持 v1 兼容一段时间后废弃
