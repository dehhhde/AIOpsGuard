### 2.4 聚合根实现 (1/1) ✅

**DiagnosisSession 聚合根** (`domain/models/diagnosis_session.py`, ~300 行)

核心职责：
1. 管理诊断生命周期（状态机）
2. 维护证据列表与根因列表
3. 发布领域事件
4. 聚合边界保护

状态转换：
```
PENDING → COLLECTING → ANALYZING → COMPLETED
                              ↓
                           FAILED
```

关键方法：
- `start_collecting()`: 开始数据采集
- `start_analyzing()`: 开始分析
- `complete()`: 完成诊断
- `fail()`: 标记失败
- `add_evidence()`: 添加证据
- `collect_events()`: 收集领域事件

验证规则：
- 状态转换合法性检查
- 证据时间范围验证
- 根因置信度验证

## 📝 关键设计决策

### 1. 为什么 TimeRange 是值对象？

**理由**：
- 不可变：时间范围一旦确定不应修改
- 无身份：两个相同时间范围是等价的
- 业务语义：封装时间范围相关的业务逻辑

### 2. 为什么 DiagnosisSession 是聚合根？

**理由**：
- 它管理聚合边界内的 Evidence 和 RootCause
- 它维护聚合的一致性（状态转换规则）
- 它是外部访问诊断数据的唯一入口
- 它发布领域事件通知外部

### 3. 为什么需要领域服务？

**理由**：
- 异常检测逻辑不属于任何单一实体
- 根因分析需要协调多个证据
- 领域服务是无状态的纯业务逻辑

### 4. 为什么使用基于规则的推理？

**理由**：
- 阶段二专注领域模型，不引入外部依赖
- 规则推理易于测试和维护
- 为阶段五的 LLM 集成预留扩展点
