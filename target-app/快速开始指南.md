# Target App 快速开始指南

## 📦 项目介绍

这是一个故意植入各类生产环境典型问题的 Spring Boot 应用，用于测试 AIOps 诊断系统的能力。

## 🎯 功能特性

### 6 种故障场景

1. **内存泄漏** - 静态集合持续累积对象
2. **线程泄漏** - 创建线程不释放
3. **慢 SQL** - 复杂数据库查询
4. **连接池耗尽** - 借出连接不归还
5. **CPU 飙高** - 密集计算占用 CPU
6. **死锁** - 线程互相等待锁

### 动态控制

- ✅ 所有问题都有开关控制
- ✅ 可通过配置文件或 API 动态启用/禁用
- ✅ 提供重置接口恢复状态

## 🚀 快速开始

```bash

mvn clean package

# 2. 运行应用

# 或使用 Spring Boot Maven 插件
```

## 🧪 测试场景

### 场景 1：内存泄漏测试

```powershell
# 1. 启用内存泄漏
Invoke-RestMethod -Uri "http://localhost:8080/api/admin/problems/switches/MEMORY_LEAK/enable" -Method Post

# 2. 触发内存泄漏（连续50次）
1..50 | ForEach-Object {
    Invoke-RestMethod -Uri "http://localhost:8080/api/leak/memory" -Method Get
    Write-Host "Request $_ completed"
    Start-Sleep -Seconds 1
}

# 3. 查看内存状态
Invoke-RestMethod -Uri "http://localhost:8080/api/leak/memory/status" -Method Get

# 4. 查看 Prometheus 指标
Invoke-WebRequest -Uri "http://localhost:8080/actuator/prometheus" | Select-Object -ExpandProperty Content | Select-String "jvm_memory"

# 5. 重置内存
Invoke-RestMethod -Uri "http://localhost:8080/api/leak/memory/reset" -Method Post
```

**预期结果**：
- 内存使用量持续增长
- `jvm_memory_used_bytes` 指标上升
- 最终可能触发 OOM

### 场景 2：线程泄漏测试

```powershell
# 1. 启用线程泄漏
Invoke-RestMethod -Uri "http://localhost:8080/api/admin/problems/switches/THREAD_LEAK/enable" -Method Post

# 2. 创建 100 个泄漏线程
1..100 | ForEach-Object {
    Invoke-RestMethod -Uri "http://localhost:8080/api/leak/thread" -Method Get
}

# 3. 查看线程状态
Invoke-RestMethod -Uri "http://localhost:8080/api/leak/thread/status" -Method Get
```

**预期结果**：
- 线程数持续增长
- `jvm_threads_live` 指标上升

### 场景 3：慢 SQL 测试

```powershell
# 1. 启用慢 SQL
Invoke-RestMethod -Uri "http://localhost:8080/api/admin/problems/switches/SLOW_SQL/enable" -Method Post

# 2. 执行慢查询
$result = Invoke-RestMethod -Uri "http://localhost:8080/api/slow/sql" -Method Get
Write-Host "Duration: $($result.durationMs) ms"
```

**预期结果**：
- 查询耗时 > 1000ms
- HTTP P99 延迟增加

### 场景 4：CPU 飙高测试

```powershell
# 1. 启用 CPU 飙高
Invoke-RestMethod -Uri "http://localhost:8080/api/admin/problems/switches/CPU_SPIKE/enable" -Method Post

# 2. 触发 CPU 飙高（持续 30 秒）
Invoke-RestMethod -Uri "http://localhost:8080/api/cpu/spike?durationSeconds=30" -Method Get
```

**预期结果**：
- CPU 使用率 > 90%
- `process_cpu_usage` 指标飙升

### 场景 5：死锁测试

```powershell
# 1. 启用死锁
Invoke-RestMethod -Uri "http://localhost:8080/api/admin/problems/switches/DEADLOCK/enable" -Method Post

# 2. 触发死锁
Invoke-RestMethod -Uri "http://localhost:8080/api/deadlock" -Method Get
```

**预期结果**：
- 检测到死锁
- 日志输出 "Deadlock detected!"

### 场景 6：连接池耗尽测试

```powershell
# 1. 启用连接池耗尽
Invoke-RestMethod -Uri "http://localhost:8080/api/admin/problems/switches/POOL_EXHAUST/enable" -Method Post

# 2. 耗尽连接池（10次）
1..10 | ForEach-Object {
    Invoke-RestMethod -Uri "http://localhost:8080/api/pool/exhaust" -Method Get
}

# 3. 尝试再次获取连接（应该失败）
try {
    Invoke-RestMethod -Uri "http://localhost:8080/api/pool/exhaust" -Method Get
} catch {
    Write-Host "Connection pool exhausted (expected)"
}

# 4. 释放连接
Invoke-RestMethod -Uri "http://localhost:8080/api/pool/exhaust/release" -Method Post
```

## 🔧 配置说明

### application.yml

```yaml
server:
  port: 8080  # 修改端口

problem:
  switches:
    MEMORY_LEAK: false  # 默认禁用所有问题
    THREAD_LEAK: false
    SLOW_SQL: false
    POOL_EXHAUST: false
    CPU_SPIKE: false
    DEADLOCK: false
```

### JVM 参数调整

编辑 `run.bat`:

```bash
java -Xms256m -Xmx512m -jar target\target-app-1.0.0.jar
```

参数说明：
- `-Xms256m` - 初始堆内存 256MB
- `-Xmx512m` - 最大堆内存 512MB
- `-XX:+HeapDumpOnOutOfMemoryError` - OOM 时生成堆转储

## 🐛 故障排查

### 问题：端口被占用

```bash
# 检查 8080 端口
netstat -ano | findstr :8080

# 杀掉进程
taskkill /PID <进程ID> /F
```

### 问题：编译失败

```bash
# 清理 Maven 缓存
mvn clean

# 强制更新依赖
mvn clean install -U
```

### 问题：OOM 后无法启动

```bash
# 增加堆内存
java -Xmx2g -jar target\target-app-1.0.0.jar

# 或重置所有问题开关
# 编辑 application.yml，将所有 switches 设为 false
```

## 📚 API 文档

### 问题触发接口

```
GET  /api/leak/memory         - 触发内存泄漏
POST /api/leak/memory/reset   - 重置内存泄漏
GET  /api/leak/memory/status  - 查看内存状态

GET  /api/leak/thread         - 触发线程泄漏
GET  /api/leak/thread/status  - 查看线程状态

GET  /api/slow/sql            - 触发慢 SQL

GET  /api/pool/exhaust        - 触发连接池耗尽
POST /api/pool/exhaust/release - 释放连接
GET  /api/pool/exhaust/status - 查看连接池状态

GET  /api/cpu/spike           - 触发 CPU 飙高（异步）
POST /api/cpu/spike/sync      - 触发 CPU 飙高（同步）

GET  /api/deadlock            - 触发死锁

GET  /api/normal              - 正常接口（基线）
```

### 管理接口

```
GET  /api/admin/problems/switches              - 获取所有开关状态
POST /api/admin/problems/switches/{type}/enable  - 启用问题
POST /api/admin/problems/switches/{type}/disable - 禁用问题
POST /api/admin/problems/switches/batch        - 批量设置开关
```

### Actuator 端点

```
GET /actuator/health      - 健康检查
GET /actuator/metrics     - 所有指标
GET /actuator/prometheus  - Prometheus 格式指标
GET /actuator/info        - 应用信息
```

## ⚠️ 重要提示

1. **仅用于测试环境** - 此应用故意包含问题，绝不可部署到生产环境
2. **资源控制** - 建议在受限环境中运行（如 Docker 容器 `-m 2g`）
3. **定期重置** - 测试后记得重置缓存和释放资源
4. **监控指标** - 配合 Prometheus + Grafana 观察指标变化
