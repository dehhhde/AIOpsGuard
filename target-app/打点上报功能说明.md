# 打点上报功能说明

## 概述

被测应用已集成完整的打点上报功能，支持多种数据采集和上报方式。

## 🎯 上报方式

### 1. Prometheus Pull 模式（默认启用）

应用通过 Micrometer 暴露指标，Prometheus 定期拉取。

**端点**: `http://localhost:8080/actuator/prometheus`

**优点**:
- 标准的 Prometheus 生态
- 无需额外配置
- 立即可用

**指标类型**:
- JVM 指标（内存、线程、GC）
- HTTP 指标（QPS、延迟、错误率）
- 数据库连接池指标
- 自定义业务指标

### 2. Kafka Push 模式（可选）

定期主动推送指标和事件到 Kafka。

**启用方式**:

编辑 `application.yml`:

```yaml
spring:
  kafka:
    enabled: true
    bootstrap-servers: localhost:9092
```

**上报内容**:

#### 指标上报（每30秒）

| Topic | 描述 | 数据结构 |
|-------|------|---------|
| `metrics.jvm` | JVM 指标 | MetricData |
| `metrics.http` | HTTP 指标 | MetricData |
| `metrics.pool` | 连接池指标 | MetricData |

**MetricData 结构**:
```json
{
  "serviceName": "target-app",
  "metricType": "jvm",
  "timestamp": "2026-11-11T10:30:00Z",
  "metrics": {
    "jvm.memory.used.heap": 524288000,
    "jvm.threads.live": 45,
    "process.cpu.usage": 0.15
  }
}
```

#### 事件上报（实时）

| Topic | 描述 | 触发时机 |
|-------|------|---------|
| `events.problems` | 问题触发事件 | 每次触发问题时 |
| `events.errors` | 错误事件 | 发生错误时 |
| `events.custom` | 自定义事件 | 业务自定义 |

**EventData 结构**:
```json
{
  "serviceName": "target-app",
  "eventType": "PROBLEM_TRIGGERED",
  "severity": "WARNING",
  "timestamp": "2026-11-11T10:30:00Z",
  "title": "Problem MEMORY_LEAK triggered",
  "description": "Problem of type MEMORY_LEAK has been triggered",
  "context": {
    "cacheSizeMB": 100,
    "usedMemoryMB": 800,
    "usagePercent": 78.5
  }
}
```

### 3. OpenTelemetry Traces（可选）

分布式链路追踪数据推送。

**启用方式**:

编辑 `application-docker.yml`:

```yaml
otel:
  exporter:
    otlp:
      endpoint: http://tempo:4317
  traces:
    exporter: otlp
    sampler:
      probability: 1.0
```

**上报内容**:
- HTTP 请求 Trace
- 数据库查询 Span
- 方法调用 Span

### 4. Loki 日志推送（可选）

日志实时推送到 Loki。

**启用方式**:

取消 `logback-spring.xml` 中 Loki Appender 的注释:

```xml
<appender name="LOKI" class="com.github.loki4j.logback.Loki4jAppender">
    <http>
        <url>http://loki:3100/loki/api/v1/push</url>
    </http>
    ...
</appender>

<root level="INFO">
    <appender-ref ref="LOKI" />
</root>
```

## 📊 指标详情

### JVM 指标

| 指标名称 | 描述 | 类型 |
|---------|------|------|
| `jvm.memory.used.heap` | 堆内存使用量 | Gauge |
| `jvm.memory.max.heap` | 最大堆内存 | Gauge |
| `jvm.threads.live` | 活跃线程数 | Gauge |
| `jvm.threads.peak` | 峰值线程数 | Gauge |
| `process.cpu.usage` | 进程 CPU 使用率 | Gauge |
| `system.cpu.usage` | 系统 CPU 使用率 | Gauge |
| `jvm.gc.pause.count` | GC 次数 | Counter |
| `jvm.gc.pause.total` | GC 总耗时 | Timer |

### HTTP 指标

| 指标名称 | 描述 | 类型 |
|---------|------|------|
| `http.server.requests` | HTTP 请求 | Timer |
| `http.server.requests.count` | 请求总数 | Counter |
| `http.server.requests.mean` | 平均延迟 | Gauge |
| `http.server.requests.max` | 最大延迟 | Gauge |

标签：`uri`, `method`, `status`

### 连接池指标

| 指标名称 | 描述 | 类型 |
|---------|------|------|
| `hikaricp.connections.active` | 活跃连接数 | Gauge |
| `hikaricp.connections.idle` | 空闲连接数 | Gauge |
| `hikaricp.connections.pending` | 等待连接数 | Gauge |
| `hikaricp.connections.max` | 最大连接数 | Gauge |

### 自定义业务指标

| 指标名称 | 描述 | 类型 |
|---------|------|------|
| `problem.memory_leak.triggered` | 内存泄漏触发次数 | Counter |
| `problem.thread_leak.triggered` | 线程泄漏触发次数 | Counter |
| `problem.slow_sql.triggered` | 慢 SQL 触发次数 | Counter |
| `problem.pool_exhaust.triggered` | 连接池耗尽触发次数 | Counter |
| `problem.cpu_spike.triggered` | CPU 飙高触发次数 | Counter |
| `problem.deadlock.triggered` | 死锁触发次数 | Counter |
| `sql.execution.time` | SQL 执行时间 | Timer |

## 🔧 使用示例

### 查询 Prometheus 指标

```bash
# 查看所有指标
curl http://localhost:8080/actuator/prometheus

# 查看内存指标
curl http://localhost:8080/actuator/prometheus | grep jvm_memory

# 查看问题触发计数
curl http://localhost:8080/actuator/prometheus | grep problem_
```

### 消费 Kafka 数据

```bash
# 消费 JVM 指标
kafka-console-consumer --bootstrap-server localhost:9092 \
  --topic metrics.jvm \
  --from-beginning

# 消费问题事件
kafka-console-consumer --bootstrap-server localhost:9092 \
  --topic events.problems \
  --from-beginning
```

### 代码中使用自定义指标

```java
@RestController
@RequiredArgsConstructor
public class MyController {
    
    private final CustomMetrics customMetrics;
    private final EventReporter eventReporter;
    
    @GetMapping("/api/my-endpoint")
    public ResponseEntity<?> myEndpoint() {
        // 记录问题触发
        customMetrics.recordMemoryLeak();
        
        // 上报事件
        Map<String, Object> context = new HashMap<>();
        context.put("key", "value");
        eventReporter.reportProblemTriggered("MY_PROBLEM", context);
        
        return ResponseEntity.ok("OK");
    }
}
```

## 📈 监控建议

### Prometheus 查询示例

```promql
# 内存使用率
100 * jvm_memory_used_bytes{area="heap"} / jvm_memory_max_bytes{area="heap"}

# 线程数趋势
rate(jvm_threads_live[5m])

# HTTP 错误率
rate(http_server_requests_seconds_count{status=~"5.."}[5m])

# HTTP P99 延迟
histogram_quantile(0.99, rate(http_server_requests_seconds_bucket[5m]))

# 问题触发频率
rate(problem_memory_leak_triggered_total[5m])
```

### Grafana Dashboard

推荐面板：
1. **JVM 监控**
   - 堆内存使用率
   - 线程数趋势
   - GC 频率和耗时

2. **HTTP 监控**
   - QPS
   - P50/P90/P99 延迟
   - 错误率

3. **问题监控**
   - 各问题触发次数
   - 问题触发趋势

4. **连接池监控**
   - 活跃连接数
   - 等待连接数

## 🚀 性能优化

### Kafka 批量上报

Kafka Producer 已配置批量发送：

```yaml
spring:
  kafka:
    producer:
      linger-ms: 100         # 延迟100ms发送
      batch-size: 16384      # 批量大小16KB
```

### 采样率控制

调整指标上报频率：

```java
// MetricReporter.java
@Scheduled(fixedRate = 30000)  // 改为 60000 (1分钟)
public void reportMetrics() {
    // ...
}
```

### OpenTelemetry 采样

```yaml
otel:
  traces:
    sampler:
      probability: 0.1  # 仅采样 10%
```

## ⚠️ 注意事项

1. **Kafka 可选** - 默认禁用，需要时启用
2. **性能影响** - 指标采集对性能影响 < 1%
3. **存储成本** - Kafka 数据需定期清理
4. **网络带宽** - 高频上报会增加带宽消耗
