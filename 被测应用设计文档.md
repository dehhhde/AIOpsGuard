# 被测应用（Target App）详细设计文档

## 1. 项目概述

### 1.1 项目定位
被测应用是一个故意植入各类生产环境典型问题的 Spring Boot 应用，作为 AIOps 诊断系统的"故障靶场"，用于验证智能诊断能力。

### 1.2 技术栈
- **框架**: Spring Boot 3.2.x
- **JDK**: 21
- **数据库**: H2（内存模式） / MySQL 8.0（可选）
- **可观测性**:
  - Micrometer（指标）
  - OpenTelemetry（链路追踪）
  - Logback（日志）
- **构建工具**: Maven 3.9+

## 3. 问题场景详细设计

### 3.1 内存泄漏（Memory Leak）

**接口**: `GET /api/leak/memory`

**实现原理**:
```java
@RestController
@RequestMapping("/api/leak")
public class MemoryLeakController {
    
    // 静态集合模拟内存泄漏
    private static final List<byte[]> LEAK_CACHE = new ArrayList<>();
    
    @Autowired
    private ProblemTriggerService triggerService;
    
    @GetMapping("/memory")
    public ResponseEntity<String> memoryLeak() {
        if (triggerService.isEnabled("MEMORY_LEAK")) {
            // 每次请求分配 10MB 数据
            byte[] leak = new byte[10 * 1024 * 1024];
            Arrays.fill(leak, (byte) 1);
            LEAK_CACHE.add(leak);
            
            log.warn("Memory leak triggered, cache size: {} MB", 
                LEAK_CACHE.size() * 10);
        }
        
        return ResponseEntity.ok("Memory leak endpoint called");
    }
    
    @PostMapping("/memory/reset")
    public ResponseEntity<String> resetMemoryLeak() {
        LEAK_CACHE.clear();
        System.gc();
        return ResponseEntity.ok("Memory leak cache cleared");
    }
}
```

**可观测数据特征**:
- **指标**: `jvm.memory.used` 持续增长，`jvm.gc.pause` 频率增加
- **日志**: `WARN Memory leak triggered, cache size: XXX MB`
- **最终表现**: OutOfMemoryError

### 3.2 线程泄漏（Thread Leak）

**接口**: `GET /api/leak/thread`

**实现原理**:
```java
@RestController
@RequestMapping("/api/leak")
public class ThreadLeakController {
    
    private final AtomicInteger threadCounter = new AtomicInteger(0);
    
    @Autowired
    private ProblemTriggerService triggerService;
    
    @GetMapping("/thread")
    public ResponseEntity<String> threadLeak() {
        if (triggerService.isEnabled("THREAD_LEAK")) {
            // 创建线程但不释放
            Thread leakedThread = new Thread(() -> {
                try {
                    Thread.sleep(Long.MAX_VALUE);
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                }
            });
            leakedThread.setName("leaked-thread-" + threadCounter.incrementAndGet());
            leakedThread.start();
            
            log.warn("Thread leak triggered, total leaked threads: {}", 
                threadCounter.get());
        }
        
        return ResponseEntity.ok("Thread leak endpoint called");
    }
}
```

**可观测数据特征**:
- **指标**: `jvm.threads.live` 持续增长
- **日志**: `WARN Thread leak triggered, total leaked threads: XXX`
- **最终表现**: 无法创建新线程，OutOfMemoryError: unable to create native thread

### 3.3 慢 SQL（Slow SQL）

**接口**: `GET /api/slow/sql`

**实现原理**:
```java
@RestController
@RequestMapping("/api/slow")
public class SlowSqlController {
    
    @Autowired
    private SlowSqlService slowSqlService;
    
    @GetMapping("/sql")
    public ResponseEntity<List<User>> slowSql() {
        long startTime = System.currentTimeMillis();
        List<User> users = slowSqlService.executeSlowQuery();
        long duration = System.currentTimeMillis() - startTime;
        
        log.warn("Slow SQL executed, duration: {} ms", duration);
        return ResponseEntity.ok(users);
    }
}

@Service
public class SlowSqlService {
    
    @Autowired
    private UserRepository userRepository;
    
    @Autowired
    private ProblemTriggerService triggerService;
    
    public List<User> executeSlowQuery() {
        if (triggerService.isEnabled("SLOW_SQL")) {
            // 模拟慢查询：笛卡尔积 + 复杂计算
            return userRepository.findAllWithSlowQuery();
        }
        return userRepository.findAll();
    }
}

// Repository
@Repository
public interface UserRepository extends JpaRepository<User, Long> {
    
    @Query(value = """
        SELECT u.* FROM users u
        CROSS JOIN users u2
        WHERE u.id = u2.id
        AND (
            SELECT COUNT(*) FROM users u3 
            WHERE u3.created_at < u.created_at
        ) > 0
        ORDER BY RAND()
        """, nativeQuery = true)
    List<User> findAllWithSlowQuery();
}
```

**可观测数据特征**:
- **指标**: `http.server.requests` 的 P99 延迟 > 5s
- **日志**: `WARN Slow SQL executed, duration: 5243 ms`
- **链路**: Span duration > 5s，数据库调用节点耗时异常

### 3.4 连接池耗尽（Connection Pool Exhausted）

**接口**: `GET /api/pool/exhaust`

**实现原理**:
```java
@RestController
@RequestMapping("/api/pool")
public class PoolExhaustController {
    
    @Autowired
    private DataSource dataSource;
    
    @Autowired
    private ProblemTriggerService triggerService;
    
    private final List<Connection> heldConnections = new ArrayList<>();
    
    @GetMapping("/exhaust")
    public ResponseEntity<String> exhaustPool() throws SQLException {
        if (triggerService.isEnabled("POOL_EXHAUST")) {
            // 获取连接但不释放
            Connection conn = dataSource.getConnection();
            heldConnections.add(conn);
            
            log.warn("Connection held, total held connections: {}", 
                heldConnections.size());
        }
        
        return ResponseEntity.ok("Connection pool exhaust endpoint called");
    }
    
    @PostMapping("/exhaust/release")
    public ResponseEntity<String> releaseConnections() throws SQLException {
        for (Connection conn : heldConnections) {
            if (!conn.isClosed()) {
                conn.close();
            }
        }
        heldConnections.clear();
        return ResponseEntity.ok("All connections released");
    }
}
```

**可观测数据特征**:
- **指标**: `hikaricp.connections.active` 达到最大值，`hikaricp.connections.pending` 增加
- **日志**: `ERROR Connection is not available, request timed out after 30000ms`
- **链路**: 数据库调用节点出现超时

### 3.5 CPU 飙高（CPU Spike）

**接口**: `GET /api/cpu/spike`

**实现原理**:
```java
@RestController
@RequestMapping("/api/cpu")
public class CpuSpikeController {
    
    @Autowired
    private ProblemTriggerService triggerService;
    
    @GetMapping("/spike")
    public ResponseEntity<String> cpuSpike() {
        if (triggerService.isEnabled("CPU_SPIKE")) {
            // 启动多个 CPU 密集型线程
            int cores = Runtime.getRuntime().availableProcessors();
            CountDownLatch latch = new CountDownLatch(cores);
            
            for (int i = 0; i < cores; i++) {
                new Thread(() -> {
                    long endTime = System.currentTimeMillis() + 30000; // 30秒
                    while (System.currentTimeMillis() < endTime) {
                        // CPU 密集型计算
                        Math.pow(Math.random(), Math.random());
                    }
                    latch.countDown();
                }).start();
            }
            
            log.warn("CPU spike triggered, {} threads running", cores);
        }
        
        return ResponseEntity.ok("CPU spike endpoint called");
    }
}
```

**可观测数据特征**:
- **指标**: `system.cpu.usage` > 90%，`process.cpu.usage` > 80%
- **日志**: `WARN CPU spike triggered, 8 threads running`
- **表现**: 接口响应变慢，其他请求受影响

### 3.6 死锁（Deadlock）

**接口**: `GET /api/deadlock`

**实现原理**:
```java
@RestController
@RequestMapping("/api")
public class DeadlockController {
    
    private final Object lock1 = new Object();
    private final Object lock2 = new Object();
    
    @Autowired
    private ProblemTriggerService triggerService;
    
    @GetMapping("/deadlock")
    public ResponseEntity<String> deadlock() throws InterruptedException {
        if (triggerService.isEnabled("DEADLOCK")) {
            CountDownLatch latch = new CountDownLatch(2);
            
            // 线程 A：先锁 lock1，再锁 lock2
            new Thread(() -> {
                synchronized (lock1) {
                    log.info("Thread A acquired lock1");
                    sleep(100);
                    synchronized (lock2) {
                        log.info("Thread A acquired lock2");
                    }
                }
                latch.countDown();
            }).start();
            
            // 线程 B：先锁 lock2，再锁 lock1
            new Thread(() -> {
                synchronized (lock2) {
                    log.info("Thread B acquired lock2");
                    sleep(100);
                    synchronized (lock1) {
                        log.info("Thread B acquired lock1");
                    }
                }
                latch.countDown();
            }).start();
            
            // 等待 5 秒，如果死锁则超时
            boolean finished = latch.await(5, TimeUnit.SECONDS);
            if (!finished) {
                log.error("Deadlock detected!");
            }
        }
        
        return ResponseEntity.ok("Deadlock endpoint called");
    }
    
    private void sleep(long millis) {
        try {
            Thread.sleep(millis);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }
}
```

**可观测数据特征**:
- **指标**: `jvm.threads.states.blocked` 增加
- **日志**: `ERROR Deadlock detected!`
- **JVM**: Thread dump 显示循环等待

  switches:
    MEMORY_LEAK: true
    THREAD_LEAK: false
    SLOW_SQL: true
    POOL_EXHAUST: false
    CPU_SPIKE: false
    DEADLOCK: false

### 4.2 控制服务

```java
@Service
public class ProblemTriggerService {
    
    @Value("#{${problem.switches}}")
    private Map<String, Boolean> switches;
    
    public boolean isEnabled(String problemType) {
        return switches.getOrDefault(problemType, false);
    }
    
    public void enable(String problemType) {
        switches.put(problemType, true);
    }
    
    public void disable(String problemType) {
        switches.put(problemType, false);
    }
    
    public Map<String, Boolean> getAllSwitches() {
        return new HashMap<>(switches);
    }
}
```

### 4.3 管理接口

```java
@RestController
@RequestMapping("/api/admin/problems")
public class ProblemAdminController {
    
    @Autowired
    private ProblemTriggerService triggerService;
    
    @GetMapping("/switches")
    public ResponseEntity<Map<String, Boolean>> getSwitches() {
        return ResponseEntity.ok(triggerService.getAllSwitches());
    }
    
    @PostMapping("/switches/{problemType}/enable")
    public ResponseEntity<String> enableProblem(@PathVariable String problemType) {
        triggerService.enable(problemType);
        return ResponseEntity.ok("Problem " + problemType + " enabled");
    }
    
    @PostMapping("/switches/{problemType}/disable")
    public ResponseEntity<String> disableProblem(@PathVariable String problemType) {
        triggerService.disable(problemType);
        return ResponseEntity.ok("Problem " + problemType + " disabled");
    }
}
```

## 7. 健康检查设计

```java
@Component
public class ProblemHealthIndicator implements HealthIndicator {
    
    @Autowired
    private ProblemTriggerService triggerService;
    
    @Override
    public Health health() {
        Map<String, Boolean> switches = triggerService.getAllSwitches();
        
        long enabledCount = switches.values().stream()
            .filter(enabled -> enabled)
            .count();
        
        if (enabledCount == 0) {
            return Health.up()
                .withDetail("problems", "none")
                .build();
        }
        
        if (enabledCount >= 3) {
            return Health.down()
                .withDetail("problems", switches)
                .withDetail("message", "Multiple critical problems active")
                .build();
        }
        
        return Health.up()
            .withDetail("problems", switches)
            .withDetail("status", "degraded")
            .build();
    }
}
```

**健康检查端点**: `GET /actuator/health`

**响应示例**:
```json

  "components": {
    "problemHealth": {
      "status": "DOWN",
      "details": {
        "problems": {
          "MEMORY_LEAK": true,
          "THREAD_LEAK": true,
          "SLOW_SQL": true
        },
        "message": "Multiple critical problems active"
      }
    }
  }
}
```

## 9. 测试验证方案

### 9.1 压力测试脚本（JMeter）

**内存泄漏场景**:
```
Thread Group: 10 threads, ramp-up 1s, loop forever
HTTP Request: GET http://localhost:8080/api/leak/memory
Duration: 5 minutes
```

**预期结果**:
- 5 分钟内触发 OOM
- Prometheus 显示内存持续增长
- 日志出现 `OutOfMemoryError`

### 9.2 功能测试清单

| 测试项 | 测试步骤 | 预期结果 |
|--------|----------|----------|
| 内存泄漏 | 连续调用 `/api/leak/memory` 50 次 | 内存增长 500MB+，最终 OOM |
| 线程泄漏 | 连续调用 `/api/leak/thread` 100 次 | 线程数增长 100+，最终无法创建新线程 |

## 12. 注意事项

5. **恢复性**: 提供重置接口（如内存泄漏清理、连接池释放），便于重复测试
